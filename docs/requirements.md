# 要件定義書 — PD Forge（仮称）

> パブリックドメイン（PD）IP を活用し、AI コーディング支援で「実用ライトアプリ」を作成・公開・販売できるプラットフォーム

- ドキュメントバージョン: 0.1（ドラフト）
- 最終更新: 2026-05-31
- ステータス: レビュー前ドラフト

---

## 1. 背景・目的

### 1.1 背景
- AI コーディング（自然言語からのコード生成）の普及により、個人がアプリを作るハードルが急速に下がっている。
- 2024〜2026 年にかけて Steamboat Willie 版 Mickey（1928）、Betty Boop 初期版、Nancy Drew 初期作などが米国でパブリックドメイン入りし、合法的に利用できる「知名度の高い IP 素材」が増えている。
- 一方で、中小・個人クリエイターが「公式（または PD）の IP を安全に使って収益化できる」プラットフォームは空白地帯になっている。
- ゲーム寄りの UGC（Roblox 等）は存在するが、**日常的に使うライトな実用アプリ（タスク管理・習慣・カレンダー等）× IP × 収益化**という領域は手薄。

### 1.2 目的
- PD IP を合法的・安全に使い、AI 支援で実用ライトアプリを作成できる環境を提供する。
- 作成したアプリをマーケットプレイスで公開・販売し、クリエイターが収益を得られるようにする。
- プラットフォームは **月額サブスクリプション + 販売手数料** を主収益とする。
- 将来的に PD IP から「中小・公式 IP のライセンス開放」へ拡張するための基盤を作る。

### 1.3 スコープ方針
- 初期（MVP）は **実用ライトアプリ（タスク管理・習慣トラッカー・カレンダー・メモ）** に限定。ゲームは対象外。
- 作成方式は **ノーコードではなく AI コーディングベース**（生成されたコードを編集・プレビュー可能）。
- 初期市場は **北米（英語）先行**。日本展開は後続フェーズ。

## 2. MVV

- **Mission**: PD のキャラクターを安全に活用し、ファンが日常ツールを作って収益を得られる場を提供する。
- **Vision**: クラシックなキャラクターたちが現代の日常に溶け込み、世界中で人々の生活を楽しくサポートし続けるエコシステムを築く。
- **Values**: Creator First / Respect IP / Accessibility / Responsible AI / Transparency

## 3. ステークホルダー / ターゲットユーザー

| 区分 | 説明 | 主なニーズ |
|---|---|---|
| クリエイター（主要顧客） | 初心者〜中級開発者、デザイナー、アニメ/クラシック文化好き | 推し PD キャラ入りアプリを素早く作り、収益化したい |
| エンドユーザー（購入者） | 生産性ツール利用者、ファン | かわいく続けやすい日常ツールが欲しい |
| プラットフォーム運営 | 自社 | 安定収益、法的リスク管理、品質維持 |
| （将来）IP ホルダー | 中小アーティスト・アニメ制作 | 追加収益源、ブランド管理、ファンデータ |

## 4. ビジネスモデル / 収益要件

| 収益源 | 内容 | 価格イメージ | 優先度 |
|---|---|---|---|
| プラットフォーム月額（主） | アプリ作成・PD アセット利用・AI 機能・公開/販売 | Basic $19/月、Pro $39/月 | 最高 |
| アプリ販売手数料 | マーケットプレイス販売額からの徴収 | 20–25% | 高 |
| POD グッズ連携 | アプリデザインのグッズ化 | 15–20% | 中（Phase 2） |
| Enterprise/教育プラン | チーム・教育機関向け | $99〜/月 | 中 |

- クリエイターの収益サイクル: 月額支払い → AI でアプリ作成 → マーケットプレイスで販売 → 月額を回収＋利益。
- 透明性要件: 手数料率・収益分配・利用制限をダッシュボードで明示。

## 5. 機能要件

優先度: ◎ = MVP 必須 / ○ = MVP 推奨 / △ = Phase 2 以降

### 5.1 AI アプリ生成（コア）◎
- 自然言語プロンプトからアプリのコードを生成（例: 「1928 Steamboat Willie Mickey を使ったタスク管理アプリを作って。完了したらアニメーションで褒めて」）。
- 生成対象スタック: **Web（Next.js）優先**。モバイル（React Native）は Phase 2。
- 生成コードのリアルタイムプレビュー（Web）。
- 追加プロンプトによる修正（「キャラを Betty Boop に変更」「もっと可愛く」）。
- 生成履歴・バージョン管理。
- コードエディタ（Cursor / Copilot 風）での手動編集。

### 5.2 PD キャラクターライブラリ ◎
- 厳選 PD アセット 10〜15 個を MVP 搭載（Steamboat Willie Mickey 1928/1930、Betty Boop 初期、Nancy Drew 初期、Einstein/Tesla/da Vinci 等）。
- 各アセットに画像・簡易アニメーション・セリフ集を付与。
- 各アセットに**スタイルガイド / 利用ルール**（商標回避、「1928 PD Version」明記、後期デザイン混入禁止）を紐づけ。
- 実在人物（Einstein 等）は「Historical Figure based on...」明記＋大幅変形を必須化。

### 5.3 サブスクリプション / 課金 ◎
- 認証・課金（Stripe）。
- プラン: Basic / Pro の 2 種。
- 利用制限（AI 生成回数、アプリ公開数等）をプランごとに設定。

### 5.4 公開・マーケットプレイス ◎（簡易版）
- 作成アプリの公開機能。
- 一覧・検索・詳細ページ。
- 購入・ダウンロード（初期は Web アプリ形式）。
- 販売額からの手数料自動徴収。
- レビュー・人気ランキング（○）。

### 5.5 管理ダッシュボード ◎
- 作成アプリ一覧、編集・公開状態管理。
- 収益ダッシュボード（売上・手数料・支払い）。
- 使用 PD アセットの利用履歴（法的証跡）。

### 5.6 審査・安全性 ◎
- AI 自動チェック（商標混同、キャラクター崩れ、禁止表現）。
- 公開前の人間審査ワークフロー（初期は運営目視）。
- 公開物への自動表記（「Based on the 1928 Public Domain version...」「AI 支援度」バッジ）。

### 5.7 透明性バッジ ○
- 各アプリに「PD バージョン使用」「AI 使用度 / 人間編集度」を表示。

### 5.8 Phase 2 以降 △
- モバイルネイティブ公開（App Store / Google Play）。
- バックエンド機能（ユーザー認証・データ永続化）の高度化。
- POD グッズ連携。
- 多言語対応。
- コラボレーション機能、分析ダッシュボード。
- 中小・公式 IP のライセンス開放（収益分配モデル）。

## 6. 非機能要件

| 区分 | 要件 |
|---|---|
| パフォーマンス | AI 生成は非同期、プレビューは即時反映。生成待ち時間の可視化。 |
| スケーラビリティ | クラウド前提（Vercel / AWS）。生成物ストレージとモデレーションを分離。 |
| 可用性 | MVP では 99% 程度を目標。決済・認証は外部 SaaS に依存。 |
| セキュリティ | 認証/認可、決済情報は Stripe に委譲（PCI 非保持）、シークレット管理。 |
| プライバシー | GDPR / CCPA 対応（同意管理、削除要求対応）。 |
| 可監査性 | PD アセット利用履歴・審査ログを保持（法的証跡）。 |
| 多通貨/税 | グローバル決済・VAT 等の税対応（段階的）。 |
| アクセシビリティ | ライト/ダークモード、モバイル閲覧対応。 |

---

## 7. 法務・コンプライアンス要件（最重要）

- **PD の地域差管理**: 米国基準で PD のものを中心に扱い、他地域ユーザーには注意喚起。地域制限/警告の実装を検討。
- **商標・パブリシティ権回避**:
  - Disney（Mickey）、Fleischer（Betty Boop）等の残存商標に注意。
  - 「1928 Public Domain Version」「Historical Figure based on...」を必須明記。
  - AI による大幅変形（カートゥーン/アニメ化）を推奨/必須化。
  - 実在人物の利用は「教育・風刺・変形」に限定。
- **AI 生成物の表示**: 人間貢献度表示・AI ラベル（米 / EU AI Act 等への対応）。
- **DMCA / Takedown 体制**: 迅速な削除フローと窓口。
- **利用規約・免責**: 利用者責任の明記、IP 専門・国際対応の弁護士レビューを前提。

## 9. ユーザー体験フロー（MVP）

1. サインアップ → 月額登録
2. PD ライブラリ閲覧 → キャラ選択
3. プロンプト入力 → AI がコード生成
4. プレビュー確認 → 追加プロンプト/手動で微調整
5. 審査（AI 自動 + 必要に応じ人間）通過
6. マーケットプレイスに公開
7. 他ユーザーが購入 → 収益発生 → ダッシュボードで確認

## 11. 成功指標（KPI 案）

- 有料登録クリエイター数 / 月次継続率（チャーン）
- 公開アプリ数、マーケットプレイス販売件数・GMV
- MRR（月次経常収益）と手数料収益
- 生成 → 公開 のコンバージョン率
- 法務インシデント件数（0 を維持）

## 12. リスクと対策

| リスク | 対策 |
|---|---|
| 商標/著作権紛争 | PD バージョン明記、AI 変形、審査、弁護士レビュー、Takedown 体制 |
